## Summary

Slides mode ships in v0.2.0, along with a minimal plugin system and the first "live slides" plugin (`slides-visuals`). The goal is simple: make it easy to turn Markdown into fixed-aspect decks and add optional visuals without bloating Kitfly's core.

## Highlights

### Slides mode (`mode: slides`)

- Single-page, hash-routed decks (`#slide-n`) with keyboard navigation
- Fixed aspect ratio with `aspect: "16/9"` (also supports `4/3`, `16/10`)
- Two authoring models:
  - one file per slide
  - explicit intra-file delimiter: `--- slide ---`
- New starter: `kitfly init --template deck`

### Plugins (minimal, pinned, integrity-checked)

- Enable via `kitfly.plugins.yaml`
- Registry-backed injection of plugin CSS/JS assets
- Version pinning (`name@x.y.z`) is required for canonical plugins
- Integrity verification with sha256 for enabled assets
- Optional `modes` allowlist to constrain where a plugin may run (`docs`, `slides`)

Documentation: `content/reference/plugins.md`

### `callouts` plugin

Styled blockquote callouts: NOTE, TIP, WARNING, INFO, DANGER. Works in both docs and slides modes. Enable with `callouts@0.2.0` in `kitfly.plugins.yaml`.

### `slides-visuals` and strict `:::` fence validation

- `slides-visuals` provides widgets + deterministic figures for slides mode
- 9 block types: kpi, stat-grid, quadrant-grid, compare, scorecard, comparison-table, layer-cake, pyramid, funnel
- The `:::` fence contract is validated when the plugin is enabled
- Invalid blocks fail fast with actionable diagnostics (file + rule), preventing silent misrenders

### Deterministic visuals: shapes and figures

Kitfly draws a clear boundary between:

- **Shapes (primitives)**: atomic building blocks with no layout logic
- **Figures**: deterministic infographic patterns that own their internal layout
- **Diagram engines**: relationship-driven auto-layout tools (Mermaid/PlantUML), best when layout is computed from a variable graph

This vocabulary is documented in the Design Catalog and reinforced by DDR-0005.

Documentation: `content/reference/design-catalog.md`

### Server management

New CLI commands for managing dev server instances:

- `kitfly servers` — list running dev servers (includes orphan detection)
- `kitfly stop <port|all>` — stop dev server(s)
- `kitfly logs <port>` — view daemon server logs (supports `--follow`)

### Site versioning

Display your site's version in the sidebar and footer across dev, build, and bundle outputs:

```yaml
version: "1.0.0"    # explicit
version: auto        # read from VERSION file
version: "file:path" # read from a specific file
```

### Brand logo fallback

When no logo file is configured or the image can't load, Kitfly renders a CSS initial (first letter of the site title) instead of showing a broken image icon.

### Bundle output separation

Bundle output now writes to `bundles/` (separate from `dist/`) so static-deploy and single-file outputs don't interfere.

## Breaking Changes

None for docs-mode sites.

If you enable `slides-visuals`, invalid `:::` blocks now stop dev/build/bundle (intentional hardening for predictable authoring).

## Migration

### Start a deck

```bash
kitfly init my-deck --template deck
cd my-deck
bun install
bun run dev
```

### Convert an existing site to slides mode

```yaml
# site.yaml
mode: slides
aspect: "16/9"
```

Then split content into one-file-per-slide, or add `--- slide ---` delimiters inside a file.

## Deferred to v0.2.1

- `slides-charts-lite`
- `slides-refresh`
- `slides-embed`
- Build-time `:::` support via a marked extension hook (v0.2.0 uses a runtime DOM transform)
