## Summary

Initial release. CLI with `init`, `dev`, `build`, and `bundle` commands. Cross-platform CI across 5 targets. Dual-format release signing infrastructure.

## Highlights

### Core functionality

- `kitfly init` — scaffold a standalone documentation site
- `kitfly dev` — development server with hot reload
- `kitfly build` — static site generation
- `kitfly bundle` — single-file HTML output with all images, styles, and scripts inlined
- Markdown rendering via `marked` (single dependency)
- Auto-discovered navigation from folder structure with hierarchical sidebar
- Bundle sidebar renders nested `<details>/<summary>` groups matching dev server
- Brand logo and favicon support in `site.yaml` (`brand.logo`, `brand.favicon`)
- Bounded logo slot (64x180px desktop, responsive down to 48x130px mobile) — handles both square marks and wide wordmarks
- Dark mode with system preference detection
- YAML-based site configuration with JSON schema validation

### Cross-platform CI

- Linux x64/arm64, macOS arm64, Windows x64/arm64
- Windows ARM64: typecheck + build validated (lint/test skipped due to missing Biome/Rollup arm64 binaries)
- Cross-platform path handling (`path.sep`, `path.resolve`) for Windows compatibility

### Release signing infrastructure

- Dual-format signing: minisign (primary) + GPG (secondary)
- SHA256 + SHA512 checksum manifests
- Separated verify targets: checksums, signatures, keys
- Provenance-only upload (CI handles tarballs)
